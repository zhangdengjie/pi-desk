## 1. 把项目跑起来

| 目的 | 命令 | 期望看到 |
|---|---|---|
| 一次性装 Wails CLI | `go install github.com/wailsapp/wails/v3/cmd/wails3@v3.1.0` + `export PATH="$HOME/go/bin:$PATH"` | `wails3 version` = 3.1.0（**必须与 `go.mod` 同版本**） |
| 热重载开发 | `wails3 dev -config ./build/config.yml -port 9245` | 窗口起来；Vite 在 9245 |
| 生产构建 | `wails3 build` → `bin/pi-desk` | 6 步链，见 `docs/01-技术架构.md` §6 |
| 打 .app / .dmg / universal | `wails3 task darwin:package` / `darwin:package:dmg` / `darwin:build:universal` | `bin/pi-desk.app`、`bin/pi-desk.dmg` |
| 起隔离验证实例（**不动你正在用的那个**） | `PI_DESK_DATA_DIR=/tmp/pidesk-sandbox/data ./bin/pi-desk.app/Contents/MacOS/pi-desk` | 日志一行 `pi-desk: sandbox instance, writable state under ...`，标题 `Pi Desk · sandbox`（`internal/appdirs/appdirs.go:87` `main.go:74`） |
| 确认只有一个实例 | `ps ax -o pid,lstart,comm \| grep 'MacOS/pi-desk' \| grep -v grep` | 一行；若双开做对比，第二行必须是沙箱 |

⚠️ 单独 `go build .` 会失败：三处 `//go:embed`（`main.go:28` `:31` `:34`）依赖 gitignored 产物。最小可用序列：

```bash
go run ./cmd/pi-desk-remote-artifacts -output build/remote-helper/artifacts \
  -build-identity pi-desk-v1.0.3-p1 -pi-min 0.84.2      # 产物 + strict manifest
cd frontend && npm install && npm run build && cd ..     # frontend/dist
go build -tags production -trimpath -buildvcs=false -ldflags="-w -s" -o bin/pi-desk .
```

## 3. 改动配方（Recipe）

### R1 给前端加一个 RPC 方法 `[~10m]` 🟢

1. 在对应 service 上加导出方法：`internal/appservice/<svc>.go`（签名必须是 `func (service *XService) Name(req domain.T) (domain.R, error)`）
2. 需要新 DTO 就加在 `internal/domain/*.go`，带 `json:` tag
3. `wails3 generate bindings -f '' -clean=true -ts -i`（或直接 `wails3 build`，deps 里会跑）
4. `wails3 task check:bindings`：生成后 `git diff --exit-code -- frontend/bindings` 必须为 0
5. 在 `frontend/src/services/<x>.ts` 加一层薄包装，store 里调它
→ **验证**：`grep -c 'export function' frontend/bindings/pi-desk/internal/appservice/<svc>.ts` 比改前 +1；`cd frontend && npx vue-tsc --noEmit` 通过

### R2 加一条界面文案 `[~5m]` 🟢

1. `frontend/src/i18n.ts` 的 `en` 与 `zh-CN` 两块**都要加**（en 在前，zh 块从 `:1388` 起）
2. 组件里 `tr("xxx.key")`；带参用 `tr("k", {count})`
→ **验证**：`npx vitest run src/i18n.test.ts`；切语言 `设置 → 语言` 看两处都变

### R3 往 `state.json` 加一个持久字段 `[~20m]` 🟡

1. `internal/workspace/catalog.go` 加字段 + 校验（上限见 `:23-28`，越界即整份保存失败）
2. `internal/domain/catalog.go` 加 DTO 字段
3. `internal/appservice/catalog.go` 两个方向都补映射：读 `:352` `GetDesktopState`、写 `:396` `SaveDesktopState`
4. 前端 `frontend/src/stores/app.ts` 的 `persistDesktopState`（`:4142`）/`loadCatalog`（`:3910`）灌进去
→ **验证**：起沙箱实例 → 改一下 → 退出 → `python3 -c "import json;print(json.load(open('/tmp/pidesk-sandbox/data/state.json'))['version'])"` 与你的新键

### R4 改流式吐字/滚动跟随 `[~10m]` 🟢

1. 默认值与夹紧逻辑：`internal/userconfig/config.go`（`DefaultReveal` `:102`、`DefaultScroll` `:106`、`normalise` `:116`）
2. 前端消费：`frontend/src/utils/streamTuning.ts` + `frontend/src/stores/app.ts:3805` `applyUserConfig`
3. 手改 `~/.pi-desk/config.json` 即可生效，不必重启（`docs/README.md` 的配置文件一节有全字段表）
→ **验证**：`go test ./internal/userconfig` + `cd frontend && npx vitest run`

### R5 加/改内嵌 Pi 扩展（todo / goal / browser / subagents / computer-use / remote） `[~30m]` 🟡

1. 扩展源码：`internal/appservice/resources/pi-desk-<name>.ts`
2. 注册与安装/卸载：`internal/appservice/extensionconfig.go:25-49`（常量 + `//go:embed`）→ 对应 `Install/Remove` 方法成对出现（`:107`…`:311`）
3. 前端面板：`frontend/src/components/PiDesk*Panel.vue` + 解析器 `frontend/src/utils/todoWidget.ts`（widget 走 Pi 的 widget 通道，不是新 RPC）
4. ⚠️ Pi 的 `/reload` **在桌面端调不到**（RPC 入站命令表没有它）。要重载就调 `app.ts` 的 `reloadThreadResources`（任务菜单「重载 Pi 资源」= 杀掉该任务 pi 进程、用同一 `sessionFile` 重启）
→ **验证**：`pidesk-shot --raise /tmp/w.png` 拍窗口并读图；或在 Pi 侧 `pi --version` 会话里看 widget 是否出现

### R6 改顶栏 / 窗口几何 / 任何 CSS `[~20m]` 🔴

必须守 `AGENTS.md` §4 三条（都是真事故换来的）：
1. 多根组件自己绑 `$attrs`（`defineOptions({inheritAttrs:false})` + 根分支 `v-bind="$attrs"`）
2. 布局属性只写在 CSS，模板不留 utility
3. **想让 CSS 隐藏一个元素，就不准在它身上留 display utility** —— `frontend/src/styles/tailwind.css:7` 是 `@import "tailwindcss" important;`，未分层的 important 在 Cascade 里反而输给分层 important
→ **验证**两条体检命令：

```bash
cd frontend && npx vite build >/dev/null 2>&1; grep -o 'display:[a-z-]*!important' dist/assets/index-*.css | wc -l   # >0 = 坑还在
grep -o '\.px-2\\\.5{[^}]*}' dist/assets/index-*.css                                                                # 看到 !important 即成立
```

### R7 加一个远程 helper 能力 `[~45m]` 🔴

四个地方必须同时改：协议帧 `internal/remoteprotocol/` → 远端实现 `internal/remotehelper/server.go` → 宿主侧 runtime `internal/remotessh/runtime_*.go` → 给 Pi 的 adapter `internal/appservice/resources/pi-desk-remote.ts`（经 `internal/appservice/remoteadapter.go:22` 内嵌）。
→ **验证**：`go test -race ./internal/remoteprotocol ./internal/remotehelper` + `wails3 task verify:ssh-live`（需 Docker）

### R8 调整 Pi 版本门槛 `[~10m]` 🟡

当前只有下限：`build/Taskfile.yml:33` 的 `-pi-min 0.84.2`（**已无 `-pi-max`**，复算：`grep -rn 'piVersionMax\|pi-max' --include='*.go' internal cmd build/Taskfile.yml` → 无输出）。校验点 `internal/remotessh/artifact.go:150`（`semver.Compare(version, minVersion) < 0` → `ErrHelperPiIncompatible`）。
改完必须重生产物再构建（否则旧产物 embed 进包）：

```bash
go run ./cmd/pi-desk-remote-artifacts -output build/remote-helper/artifacts -build-identity pi-desk-v1.0.3-p1 -pi-min 0.84.2
python3 -c "import json;a=json.load(open('build/remote-helper/artifacts/manifest.json'))['artifacts'];print(sorted({(x['os'],x['piVersionMin']) for x in a}))"
```

### R9 加一个整页（新 `AppPage`） `[~25m]` 🟡

`frontend/src/stores/app.ts:86` 的 `type AppPage = "task" | "scheduledTasks"` 加成员 → store 里 `open…()`（参 `:2506`）→ `frontend/src/App.vue:143` 的布局 class 判定 + `:163` 的 `v-if` 挂载 → 侧栏入口 `AppSidebar.vue` → i18n。
→ **验证**：`pidesk-shot --raise /tmp/page.png` 拍图确认布局没把 inspector 挤掉

## 4. 测试怎么分层跑

| 层 | 命令 | 覆盖 | 备注 |
|---|---|---|---|
| Go 单测 | `TMPDIR=/tmp go test ./...` | 111 个 `*_test.go` | CI 只在 **linux** job 跑；默认 `TMPDIR` 过长会让 appservice 的 socket 测试误报 |
| Go vet | `go vet ./...` | — | 同上 |
| 竞态 | `go test -race -count=1 ./internal/remoteprotocol ./internal/remotehelper` | 远程协议/helper | CI linux job |
| Fuzz（各 10s） | `go test ./internal/remoteprotocol -run '^$' -fuzz '^FuzzReaderNeverPanics$' -fuzztime=10s`（另有 `FuzzValidateRelativePath`、`FuzzParseHostKeyEvidence`） | 解析器不 panic、目录逃逸、host key 证据 | CI linux job |
| 前端全家桶 | `cd frontend && npm run check` | = `typecheck` + `vitest run`（109 个 `.test.ts`）+ `vite build` + `smoke:dist` | 单跑：`npx vitest run src/stores/app.test.ts` |
| 活体（真装的 pi/shell） | `wails3 task verify:pi-live`（内部 `PI_DESK_LIVE_TEST=1`） | `piruntime` `remotessh` `terminal` `sessionindex` | 前置：`pi --version` 可用（`Taskfile.yml` `verify:pi-live.preconditions`） |
| 远程验收矩阵 | `wails3 task verify:ssh-live` → `sh test/sshfixture/verify.sh` | 隔离 Docker：密码/加密 key/proxyjump/无 home/只读/admin/toxiproxy | 前置 Docker + npm |
| Windows 冒烟 | `wails3 task verify:windows-smoke` | 打包后的窗口存在且非空白 | `test/smoke/windows-app.ps1` |

活体开关的判据：`grep -rn 'PI_DESK_LIVE_TEST' --include='*_test.go' internal` → 每处都 `t.Skip`，所以 `go test ./...` 默认是干净的。

## 5. 排障：症状 → 定位顺序 → 处理

| 症状 | 按这个顺序查 | 处理 |
|---|---|---|
| 启动就退，日志只有一句 manifest 相关 | ① `ls build/remote-helper/artifacts/` ② `python3 -c` 打 `manifest.json` 的键 | 先跑 R8 的产物命令**再** `wails3 build`（`internal/remotessh/artifact.go:58` 是 strict + `DisallowUnknownFields`） |
| `workspace is not registered` | ① `ps ax \| grep MacOS/pi-desk` 是否两行 ② 该 thread 的 `workspaceId` 能否在 `state.json` 的 `workspaces[]` 找到 ③ 路径归一化后是否相等 | 单实例锁已兜（`main.go:88`）；要双开就 `PI_DESK_ALLOW_MULTI_INSTANCE=1` 并先退掉真实例 |
| 「文件」面板满屏 `工作区访问已禁用` | ① catalog 里该 workspace 的 `trust` ② 是不是 `discovered`（Pi 目录有、catalog 没有 → 设计如此） ③ `thread.trust` 与 catalog 是否一致（`frontend/src/stores/app.ts:3990`） | 设置里改信任；**不要**去改前端 gate（真相源唯一，`AGENTS.md` §1） |
| 默认模型变了 + 思考等级下拉空白 | ① `python3 -c` 打 `~/.pi/agent/models.json` 看有没有 `"apiKey": "$VAR"` ② `launchctl getenv DASHSCOPE_API_KEY \| wc -c` | 0/1 = GUI 拿不到 → `launchctl setenv ...` + **重开 App**；根治见 `AGENTS.md` §7 与 `internal/appservice/modelconfig.go:566` |
| 远程 workspace 起不来、本地正常 | ① `pi --version` ② `internal/remotessh/artifact.go:150` 的 min 比较 ③ lease 日志 | 重生产物（R8），或本地先跑 `verify:ssh-live` |
| 找不到 `pi` / runtime 起不来 | `Resolve()` 只有 `LookPath("pi")`，**无兜底路径**（`internal/piruntime/locator.go:91`） | 终端启动看 PATH；GUI 启动改 launchd 域 PATH（`docs/DEV_RUN.md` §5.1） |
| `wails3 dev` 起不来：`9245 address already in use`，但 `ps \| grep wails` 空 | 真凶是孤儿 node/vite（PPID=1） | `lsof -nP -tiTCP:9245 -sTCP:LISTEN \| xargs kill`，或 `WAILS_VITE_PORT=9246` |
| 刚重签过，截图/录屏授权又失效 | ad-hoc 签名每次 cdhash 变 → TCC 视为新 App（`AGENTS.md` §2.5） | 系统设置里关掉再打开授权 + Cmd+Q 重开；根治要 Developer ID |
| 要看某个界面到底长什么样 | `pidesk-shot --raise /tmp/x.png` 然后**读那张图**（前台窗口才行；`--list` 的 title 全空 = 没授权） | 没有沙箱实例它自己起一个（`docs/DEV_RUN.md` §3.1.1） |
| 想看 pi 那一侧到底回了什么 | ① `GetDiagnostics`（`internal/appservice/agent.go:845`）透传子进程诊断 ② dev 构建开 DevTools（`main.go:352` `buildinfo.DevTools`） ③ 宿主日志 `log show --last 5m --predicate 'process == "pi-desk"'` | 帧级证据才写进结论（`AGENTS.md` §6） |

## 6. 提交前固定动作

```bash
git checkout -- frontend/package-lock.json   # npm 11 每次 build 会删 54 行 libc 字段
go test ./...                                # 至少别把红的带走
cd frontend && npm run typecheck
```

- `docs/`、`AGENTS.md`、`bin/`、`frontend/dist/`、`build/remote-helper/artifacts/` 都在 `.gitignore` 里 → 本地笔记不会进 PR
- 上游 PR 未合并前只 push `fork`，且**永远显式带分支**：`git push fork develop`（禁止裸 `git push` / `git push origin`）
- 网络被代理掉时的两条端口试法与核对命令见 `AGENTS.md` §5 末节
